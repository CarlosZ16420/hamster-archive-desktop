# Hamster Archiver · UI 优化方案（NEWUI）

> 版本：2026-08-21 · 面向 v4.2.1 现版 UI
> 配套交互演示：本目录下的 `demo/index.html`（直接用浏览器或 Electron 打开即可，数据为演示数据）

---

## 0. 这份方案怎么用

`demo/` 是一个**独立的静态交互原型**，不依赖 Electron，不含任何项目代码改动。它复刻了现版的功能布局，并用「构造测试目录」中的真实图片/视频作为演示素材。

演示里有两个**演示专用**的控件，用于对比，落地时不需要实现：

| 控件 | 位置 | 作用 |
|---|---|---|
| 「对比现行网格算法」开关 | 仓库页工具栏右侧 | 勾选后网格退回现版 `auto-fill` 布局，并用虚线标注出右侧空白宽度；取消勾选恢复新版算法 |
| 顶栏「NEWUI 提案」徽章 | 顶栏 | 标识这是提案演示 |

建议体验顺序：

1. **归档工作台**：看「高级压缩设置」折叠组 → 展开它 → 修改格式/等级/命名/分卷开关 → **注意组头的摘要行实时变化**；再看看队列工具栏（先点几个任务复选框）。
2. **仓库**：拖动浏览器窗口宽度，观察卡片如何**恰好填满**每行；勾选「对比现行网格算法」再拖一次，看右侧空白标注；切到「列表」视图看纯文本列表；点任意卡片打开详情抽屉（视频条目有内嵌预览）。

## 1. 现状诊断

### 1.1 工作台设置过载

`index.html:100-188` 的单个 `<details class="advanced">`「高级设置」目前承载了：用户数据区、压缩暂存目录、解压密码、视频帧备份、小项目过滤、定时运行、相似度排除词表、缩略图上限、压缩格式、压缩率、压缩包命名方式 —— **11 组互不相关的设置挤在一个抽屉里**。

后果：

- **语义混杂**：「压缩格式」和「用户数据区」属于完全不同的关注层（任务参数 vs 应用维护），却平级排列；
- **折叠等于失忆**：`<details>` 收起后没有任何状态反馈，用户必须展开才能确认"我现在用的是 7z 还是 ZIP、有没有设密码"；
- **主流程被淹没**：01 面板同时暴露路径、三种后处理方式、备份位置……第一屏的认知负担过大。

### 1.2 列表模式定位模糊

现版「列表」模式（`app.js:renderCatalog` + `styles.css:471-492`）是**左侧 260-330px 的缩略图卡片窄列 + 右侧详情**。它和「大缩略图」模式的区别只是卡片小一点、排成一列 —— 两种模式都在展示图片，**信息结构没有差异化**。当用户想"按信息找东西"（审计、批量整理、核对大小）时，没有任何一种视图能提供高信息密度。

### 1.3 大缩略图右侧空白

`styles.css:494`：

```css
.library-layout.grid-mode .catalog-list {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(230px, 280px));
  justify-content: start;
}
```

**根因**：`auto-fill` 按**每列最大宽度 280px** 计数能容纳的列数。当容器宽度略低于"再多放一列"的阈值时，已无法增加列，已生成的列又已被 `max` 封顶在 280px，于是剩余空间全部堆在右侧。以容器 1297px 为例：4 列 × 280px + 3 × 16px 间距 = 1168px，**右侧空白 129px**；最坏情况下空白可达约 295px。拉伸卡片（`1fr`）已被你正确否决 —— 卡片会随窗口无限变宽变丑。

## 2. 设计原则

1. **一屏一个主行动**。每个视图只有一个 primary 按钮（工作台是「开始压缩入库」，仓库是内容本身）。
2. **折叠 ≠ 隐藏**。任何折叠组收起时，组头都保留一条**摘要行（digest）**，实时显示当前生效配置。展开只为了"改"，不为了"看"。
3. **按使用频率分层**。每次归档都要看的（路径）永远可见；偶尔调的（压缩参数、后处理）折叠但带摘要；基本不动的（用户数据区、词表）收进「更多设置」。
4. **操作跟着选择走（情境化）**。批量操作只在选中内容后出现；常驻按钮堆 → 按钮菜单 + 二次确认。
5. **两种视图两种职责**。大缩略图 = 视觉浏览/回忆；文本列表 = 信息密度/核对。不再互相模仿。
6. **布局用数学，不用巧合**。网格列数按容器实测宽度计算，卡片宽度在**设计区间 [236px, 312px] 内**精确分配剩余空间 —— 是"区间内微调"（每张卡最多 ±15%），不是 `1fr` 式粗暴拉伸。

## 3. 归档工作台重组

### 3.1 信息架构映射

| 新分组 | 可见性 | 吸收的现有控件（现 ID） |
|---|---|---|
| **01 收存位置** | 始终展开 | `intake-directory`、`archive-output-directory` |
| **归档后处理** | 折叠 + 摘要 | `move-completed`、`processed-source-directory`、`record-backup-location`、`backup-location`、`auto-trash-completed` |
| **高级压缩设置**（新折叠组） | 折叠 + 摘要 | `archive-format`、`compression-level`、`archive-naming-mode` 三个 radio、`custom-archive-name`、`archive-password`、`record-archive-password`、**＋ 新增分卷压缩设定** |
| **入库与预览** | 折叠 + 摘要 | `video-frame-backup`、`video-frame-count`、`thumbnail-limit`、`small-item-filter`、`minimum-task-mb` |
| **更多设置** | 折叠 + 摘要 | `schedule-enabled/start/end`、相似度排除词表、`user-data-path`、`archive-staging-directory` |

页面骨架从"01 大面板塞一切"变为**双栏**（≥1120px）：左栏全部设置（sticky），右栏队列与日志。窄窗口自动退回单栏。逻辑依据：设置是"一次配好偶尔改"，队列是"持续注视的对象"，两者视线焦点不同，不该纵向挤在一列里互相推搡。

### 3.2 摘要行（digest）规格

折叠组头部结构：`组名 · 摘要行 · 展开箭头`。摘要由控件值实时拼接：

```
高级压缩设置   7z · 等级 1 · 时间戳命名 · 不分卷 · 无密码                    ▾
归档后处理     移动到「已备份」 · 记录备份位置 · 不用回收站                  ▾
入库与预览     视频抽帧 3 帧/视频 · 缩略图上限 30 张 · 过滤 <100 MB          ▾
```

实现上是一个 `updateXxxDigest()` 函数族挂在对应控件的 `input/change` 事件上（demo `demo.js` 中有完整参考实现，约 40 行）。**这是本提案中性价比最高的单项改动**：用户 90% 的时间只需要看摘要，不需要展开。

### 3.3 分卷压缩设定（新增）

现状：README 中"超过 10 GiB 的任务自动拆分"是一条**隐式规则**，UI 上不可见、不可调。方案将其显式化：

```
☑ 分卷压缩   超过单卷上限的任务自动拆分为多个分卷（7z -v）
   单卷大小  [ 4096 ] [GB ▾]
   示例：一个 9.8 GB 的任务将拆为 3 卷（4 + 4 + 1.8 GB）
```

- **默认值 10 GiB**，与现行为完全一致（老用户无感知变化）；
- 关闭开关 = 摘要显示「不分卷」，即维持"单个任务不主动分卷"的语义（10 GiB 熔断规则是否保留由你决定，建议保留为独立的安全机制并在文档中说明）；
- 示例行实时按 `ceil(任务大小/单卷大小)` 计算，让"分卷"这个抽象概念可预期；
- 数据模型：settings 增加 `archiveVolumeBytes`；`archive-engine.js` 对接 7z `-v{size}b` 参数；仓库记录已有 `volumes` 概念，卡片上以「N 卷」徽章呈现（demo 已演示）。

### 3.4 队列工具栏情境化

现状（`index.html:220-229`）：6 个按钮常驻 —— 移除所选 / 清除可能重复 / 清除精确重复 / 同意全部重复 / 清空已完成 / 一键清空。前 5 个在无选中时全是噪音，「一键清空」这个高危按钮更是与普通操作平级裸露。

新版：

- **无选中**：只显示轻提示「点击任务行的复选框可进行批量操作」；
- **有选中**：出现「已选 N 项 · 移除所选 · 重复项处理 ▾ · 清理 ▾」；
- 「清除可能重复 / 清除精确重复 / 同意全部重复」收进**重复项处理**菜单；「清空已完成 / 一键清空」收进**清理**菜单，后者保留现有的确认流程；
- 「开始压缩入库」保持唯一 primary；「完成这一项暂停」在队列运行时才出现（现版已有此逻辑的雏形，`pause-queue`/`resume-queue` 的 hidden 切换可以复用）。

### 3.5 运行记录

日志面板同样折叠 + 摘要：收起时组头显示**最新一条日志**（时间 + 文本），点开看全量。运行状态徽章（空闲/运行中）保留在组头右侧。

## 4. 仓库页

### 4.1 列表模式：回归纯文本

砍掉左侧缩略图窄列，改为**全宽文本列表**（demo 中已实现）：

| 列 | 内容 | 对齐 |
|---|---|---|
| ☑ | 选择框 | — |
| 名称 | 标题 + 内联标签（含「未压缩」「可能重复」警示标签） | 左 |
| 类型 | 文件夹 / 视频 / 手动 | 左 |
| 文件 | 数量（右对齐，表格数字） | 右 |
| 大小 / 状态 | `2.2 GB · 2卷` 或 `未压缩`（警示色） | 左 |
| 入库时间 | `2026-08-19` | 左 |
| 星级 | ★★★★☆ | 左 |

要点：

- **零图片**。缩略图浏览是大缩略图模式的职责，列表模式的职责是"一屏 12-15 行扫完关键信息"；
- 行高 52px，支持 hover / active / selected 三态，点击行打开详情（与卡片一致）；
- 窄屏（<1080px）自动收起 类型/文件/星级 三列。

### 4.2 详情：统一为右侧抽屉

现状是双轨制：列表模式详情在右栏，网格模式详情在内容区下方（`styles.css:502`），两套布局两套体验。新版统一为**右侧滑入抽屉**（500px，Esc / 点遮罩关闭）：

- 封面区：图片条目显示封面；**视频条目直接内嵌 `<video>` 播放**（demo 用测试目录的真实视频片段演示）；
- 元信息：文件数、原始大小、压缩状态（格式+等级）、分卷、入库时间、压缩包命名 —— 六宫格；
- 标签与标记区（含备份位置、可能重复）；
- 缩略图条（带「封面」角标，点击进灯箱 —— 灯箱本身沿用现版）；
- 操作：校验完整性（primary）/ 打开压缩包位置 / 编辑信息。

收益：两种视图的交互模型完全一致；`renderCatalogDetail`（app.js:1505）从"两种容器各渲染一份"简化为"一个抽屉"。

### 4.3 大缩略图网格：按容器测量（核心算法）

```js
const GAP = 16, MIN = 236, MAX = 312, IDEAL = 272;

function layoutGrid(grid) {
  const W = grid.clientWidth;
  if (W <= 0) return;
  // 能让每张卡都 ≤ MAX 的最少列数；能让每张卡都 ≥ MIN 的最多列数
  const nMin = Math.max(1, Math.ceil((W + GAP) / (MAX + GAP)));
  const nMax = Math.max(1, Math.floor((W + GAP) / (MIN + GAP)));
  // 取设计理想宽度附近的列数，clamp 进 [nMin, nMax]
  const cols = Math.min(Math.max(Math.round((W + GAP) / (IDEAL + GAP)), nMin), nMax);
  let cardW = (W - (cols - 1) * GAP) / cols;   // 精确吃满容器
  let justify = 'start';
  if (cardW > MAX) { cardW = MAX; justify = 'center'; }  // 容器过窄时优雅退化
  grid.style.gridTemplateColumns = `repeat(${cols}, ${cardW.toFixed(2)}px)`;
  grid.style.justifyContent = justify;
}
```

**为什么这不算"粗暴拉伸"**：卡片宽度被硬约束在 [236, 312] 设计区间内 —— 无论容器多宽，单张卡与 272px 理想值的偏差不超过 ±15%，肉眼上"始终是同一种卡片"；而 `1fr` 方案会随窗口把卡片拉到 400px+。区别在于**区间内微调** vs **无界拉伸**。

边界情况：容器窄到连 2 列都放不下 `[MIN, MAX]` 区间时（如 700px 宽），卡片封顶 312px 并**整体居中** —— 空白是对称分布的、有意的，而不是堆在一侧的、意外的。

实现要点：

- 用 `ResizeObserver` 监听容器（现版 `app.js` 已有 `measureCatalogGridColumns()` 的思路，等于把它从"算分页大小"扩展为"定列宽"）；
- 切换到仓库标签页时重排一次（demo 的 tab 切换处已演示）；
- 实测数据（Electron 无头测试）：容器 1197px → 4 列 × 287.25px，**行末像素级填满**；同一宽度下现版算法为 4×280px + 右侧空白 129px。

### 4.4 批量操作栏情境化

与队列工具栏同一原则：未选中时只显示提示文案；选中后出现「批量追加标签 / 修改备份位置 / 压缩入库 / 删除所选…」。「手动新增库存」右置为常驻 secondary。

## 5. 视觉密度

- **顶栏替代 hero**：现版 hero（`仓鼠症大结局` + 大标题 + 副标题）占用约 200px 高度的黄金区域。新版改为 54px 应用栏（logo + 导航 + 主题/语言/安全徽章），页面内容直接上移。**这是可选项** —— 如果你舍不得 hero 的品牌感，可以保留但压缩为一行高的 banner；核心收益是首屏多出 150px 给队列/仓库。
- 字号阶梯收紧：正文 13px、元信息 11.5-12px、标题 17px，减少层级跳跃；
- 面板圆角统一为 16px / 组内元素 12px / 输入 8px 三级；
- 现有 day/night 双主题的语义变量体系**原样保留**（demo 的 CSS 变量名与现版 `styles.css` 一一对应），落地时只搬结构、不动 token，主题零成本。
- 日志、热力图、随机漫步、分页、灯箱等既有组件保持原有行为，不在本提案范围内动。
